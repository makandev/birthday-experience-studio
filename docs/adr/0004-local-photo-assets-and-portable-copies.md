# ADR 0004 – Local photo assets and portable recipient copies

Status: accepted for evolving 0.2 foundations.

Binary media belongs in IndexedDB, not CreatorProject/localStorage. A typed source discriminant (`local | external | unavailable`) keeps the model extensible for audio/video. Original raster bytes and processed derivatives are separate immutable asset records. Import detects PNG/JPEG/WebP signatures and dimensions before decoding, rejects unsupported SVG/GIF/animated WebP and pixel bombs, normalizes orientation through the browser decoder, scales and re-encodes pixels as bounded JPEG. Original files are never overwritten; recipients only receive the derived image. Transparent input is flattened onto a light background. APNG is flattened to the browser's decoded still frame, not exported as animation.

Budgets: six photos per project; 8 MiB per original; 24 MP source; 1600 px maximum rendered edge / 2 MP rendered area; 512 KiB per derivative; 6 MiB recipient HTML; 8 MiB portable draft including processed photos and at most 2 MiB project text. Original archives remain subject to browser quota. Codec processing strips original EXIF/comment metadata; export additionally rejects derivatives carrying those JPEG markers. These are layered checks, not proof against every browser codec vulnerability.

A photo block owns explicit alt/caption and allowlisted contain/cover plus center/top/bottom positioning. Directions style the photo consistently as soft, polaroid or wide. Gift projection resolves only selected image sources, excludes original bytes/names/IDs/metadata and fails closed on missing assets. Async preview uses a snapshot/generation token so stale asset reads cannot replace newer choices. Recovery keeps a visible explanatory frame instead of loading a new document in a display:none frame, which left the managed Chromium renderer without layout after source errors.

Portable creator drafts contain revalidated/reprocessed gift-sized derivatives, not originals. Import remaps asset IDs, stages bytes in memory until confirmation, writes them transactionally in IndexedDB, then activates the project. Project switching and the asset transaction are not one cross-database transaction; a failed activation may leave harmless unreferenced assets for future cleanup, but cannot overwrite a previous original. Originals can be separately downloaded from their source device. Removing a photo from a gift removes its references but keeps local assets for undo/recovery; permanent cleanup is future work and explicitly disclosed.

Optional external photos use validated public HTTPS URLs without credentials/queries/ports, explicit Online consent, an origin-bounded CSP, no referrer and persistent descriptive fallback text. The Studio never processes external pixels or acts as a media proxy. Only local photos can guarantee an offline image. Imported external consent is reset. External resources can fail or reveal recipient IP/cookies to their host; the consent warning is required. Remote SVG returned as an image is browser image context, not user HTML; no local SVG import or script-capable embedding is permitted.

No new runtime dependencies. Native canvas, image decoding and IndexedDB suffice for the first foundation. Advanced lossless processing, galleries/timelines/fullscreen, cleanup and audio playback remain future milestones.
